# Contributing to AlphaFit API

Thank you for your interest in contributing to AlphaFit API.

## Development Workflow

All changes should be developed in a dedicated branch created from `main`.

### Branch Naming

Use descriptive branch names:

- `feature/feature-name`
- `fix/bug-name`
- `refactor/refactor-name`
- `hotfix/issue-name`

Example:

    feature/member-management

## Pull Requests

All changes should be submitted through a Pull Request before being merged into `main`.

A Pull Request should:

- Clearly describe the changes
- Explain the purpose of the change
- Include relevant tests
- Follow the project's existing architecture and conventions
- Avoid unrelated changes

## Commits

Write clear and descriptive commit messages.

Examples:

    feat: add member management
    fix: prevent duplicate monthly payments
    refactor: improve authentication service
    test: add payment validation tests

## Code Quality

Contributions should prioritize:

- Readable and maintainable code
- Separation of responsibilities
- Proper validation
- Secure implementation
- Appropriate test coverage
- Consistency with Laravel conventions

## Issues

Before opening a new issue, check whether a similar issue already exists.

When reporting a bug, provide:

- Description
- Steps to reproduce
- Expected behavior
- Actual behavior
- Relevant environment information

## Security

Do not publicly disclose security vulnerabilities through Issues.

For security-related reports, please follow the instructions in `SECURITY.md`.
